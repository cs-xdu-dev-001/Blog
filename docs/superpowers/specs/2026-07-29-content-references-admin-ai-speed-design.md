# 内容引用与后台AI响应优化

## 目标

本次只完成两项：

1. 在笔记编辑器中快速引用站内公开内容，并在目标详情页展示引用它的笔记。
2. 缩短后台笔记AI的首字等待时间，后台请求固定使用`gpt-5.5`。

不新增首页模块，不建设通用知识图谱，不改变前台AI助手模型。

## 内容引用

### 编辑体验

- 在Milkdown编辑器输入`[[`后打开光标旁的搜索面板。
- 搜索范围包括公开笔记、主线、书籍、影像和美食。
- 搜索结果显示类型与标题，键盘支持上下选择、回车插入、Esc关闭。
- 选择结果后写入普通Markdown链接，`[[`只负责触发搜索，不进入最终正文。

示例：

```markdown
[AI时代的技术学习流程](/posts/ai-era-learning)
```

### 数据与查询

- 复用现有全站搜索结构，但通过管理员接口返回可引用内容。
- 仅返回公开且存在稳定前台地址的条目，避免插入访问后404的草稿链接。
- 不新增关系表。
- 反向引用通过公开笔记正文中的规范站内链接按需查询。
- 反向引用来源第一版仅限笔记，目标可为笔记、主线、书籍、影像或美食。

### 前台呈现

- 在对应详情页正文末尾显示引用当前内容的笔记。
- 没有引用时不渲染空模块。
- 受保护笔记不参与公开反向引用结果。

## 后台AI

### 模型与范围

- 后台笔记AI请求固定使用`gpt-5.5`。
- 前台博客AI继续使用原有站点配置。
- 有选区时，仅发送选中文字、前一段和后一段。
- 没有选区时发送当前笔记正文，但保留明确的最大长度限制。
- 最近对话轮数从当前8轮收紧到完成任务所需的最小范围。

### 请求链

- 润色、压缩、重写和续写使用快速编辑链。
- 快速编辑链直接请求替换文本，不要求模型先生成完整JSON提案。
- 服务端读取第三方API的流式增量并立即转发给管理端。
- 自由问答和复杂修改继续使用现有Agent链，避免把所有能力塞进快速链。
- 请求可取消；新请求开始时终止同一编辑器中的旧请求。

### 编辑器反馈

- 生成内容在编辑区的审阅层逐步显示。
- 原文始终保留，AI不能直接保存或覆盖正文。
- 用户点击确认后才应用修改，放弃后恢复原编辑状态。
- 选区任务只替换原选区；整篇任务才允许替换全文。
- 记录首字耗时和总耗时，错误信息区分本地校验、上游HTTP错误和超时。

## 错误边界

- `gpt-5.5`不可用时返回明确的模型错误，不静默切换模型。
- 搜索失败不影响编辑器正文，面板显示重试入口。
- 引用目标删除后保留普通Markdown链接，不自动改写历史正文。
- 流式响应中断时保留已生成内容供查看，但禁止确认不完整结果。

## 测试

- `[[`触发、搜索、键盘选择和Markdown链接插入。
- 各内容类型的稳定URL与公开状态过滤。
- 反向引用查询不泄露草稿或受保护笔记。
- 选区请求只包含选区和邻近段落。
- 后台请求模型为`gpt-5.5`，前台AI配置不受影响。
- 流式增量、中断、取消和最终确认。
- 完整测试与生产构建继续通过。
