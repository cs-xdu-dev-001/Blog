# 管理端内嵌Agent设计

## 目标

在笔记编辑器内加入类似Cursor的右侧Agent面板。Agent能够读取当前笔记和选区、连续对话并提出内容修改；任何修改都先展示对比，只有用户接纳后才写入编辑器。

## 范围

第一版只服务笔记编辑，不扩展文件树、终端、插件市场或站点管理工具。

- 右侧停靠面板，可展开、收起和调整宽度。
- 当前笔记正文自动作为上下文，存在选区时优先处理选区。
- 支持连续对话、停止当前请求和清空对话。
- 支持普通回答和内容修改建议。
- 修改建议沿用现有原文/AI结果对比与接纳机制。
- 对话只保存在当前浏览器会话，不新增数据库表。
- 继续使用管理端现有AI接口配置，不增加重复的密钥和模型设置。

## 界面

编辑器顶部增加一个图标按钮，用于展开或收起Agent。展开后，编辑区域与Agent面板并排，面板默认宽度约380px，可在合理范围内拖动调整。

面板只保留四个区域：

1. 简短工具栏：新对话、收起。
2. 消息区：用户和Agent消息、生成状态、错误及重试。
3. 修改建议：仅在Agent提出修改时出现，显示查看对比、接纳和放弃。
4. 输入区：多行输入、发送和停止。

不使用大标题加小字说明，不展示冗余欢迎页，不常驻快捷操作卡片。

## 架构

### 前端

新增独立的Agent面板脚本，负责面板状态、对话记录、请求取消和宽度调整。Milkdown脚本只暴露三个明确能力：

- 读取当前全文与选区。
- 将AI建议交给现有对比面板。
- 在用户接纳后替换选区或全文。

Agent面板不直接操作ProseMirror内部状态。

### 服务端

新增管理端Agent接口，继续复用`siteConfigRepository`中的AI配置和`assistantService.mjs`中的请求适配。

请求包含：

- 当前用户消息。
- 最近8轮对话。
- 当前笔记标题、摘要和正文。
- 当前选区。

服务端返回：

- `message`：对用户的回答。
- `proposal`：可选的Markdown修改建议及作用范围。

第一版使用现有OpenAI兼容提供器。提供器调用保持在服务端，浏览器无法读取API密钥。Agent接口与界面不绑定具体模型，后续可增加Codex SDK适配器。

## 修改安全

- Agent永远不能直接保存笔记或写数据库。
- Agent提出的修改只进入对比面板。
- 只有点击接纳才更新Milkdown内容，之后仍需点击页面原有保存按钮。
- 加密笔记沿用现有管理员解锁逻辑，未解锁正文不会发送给模型。
- 服务端限制正文长度、对话轮数和单条消息长度。

## 错误处理

- 请求可通过停止按钮中断。
- HTTP错误显示明确状态，并保留原输入供重试。
- 空回答不会创建Agent消息。
- 新请求发起时禁止重复提交。
- 关闭面板不会丢失当前页面会话；刷新页面后清空。

## 验证

- 源码测试锁定面板结构、上下文获取、取消、清空和diff接纳边界。
- 服务测试覆盖未配置、普通回答、修改建议、超限输入和请求中断。
- 构建验证Milkdown懒加载和现有预览、保存功能不受影响。
- 桌面浏览器验证面板展开、收起、调宽、滚动和编辑区布局。
